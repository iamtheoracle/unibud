# UNIBUD Experience Design Principles

## Product feel

UNIBUD should feel like one coherent product with several useful spaces, not a collection of unrelated apps pasted together. Navigation should make the spaces understandable without filling every screen with every capability.

## Principles

- Keep the primary screen focused on the user's current purpose.
- Use progressive disclosure for advanced controls.
- Make each space recognisable through its information hierarchy and interaction model.
- Do not duplicate the same feed or dashboard in every space.
- Keep academic work, general entertainment, dating, support, marketplace, and financial tasks distinct.
- Use clear language and meaningful empty states; never use fake activity or sample financial data as if real.
- Design mobile-first, with responsive desktop layouts for administration and operations.
- Accessibility, keyboard use, readable contrast, reduced motion, and assistive technology are baseline requirements.

## Navigation

The global shell should expose the ecosystem without forcing every space into a fixed bottom navigation. Contextual navigation belongs within each space. Preserve orientation when moving between spaces and clearly identify when a user enters a sensitive or staff-only workflow.

## Design system

Tokens, components, motion, typography, and icon rules should be documented and tested in a shared design system. Visual polish must not substitute for functional and security validation.
