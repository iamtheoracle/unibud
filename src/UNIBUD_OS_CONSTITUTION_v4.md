# UNIBUD OS v4 Constitution

> **The single source of truth.**
>
> Every AI agent, every feature, and every future developer must obey this
> document. It comes before implementation. Every prompt, every task, every
> feature is validated against this constitution before development begins.

---

## 1. Philosophy

UNIBUD is one operating system, not a collection of apps.

Users should never feel like they are switching between separate products.
Every experience is part of one continuous system.

## 3. The Seven Experiences

These never change.

1. **Square**
2. **Campus**
3. **Quad**
4. **Connect**
5. **Lens**
6. **Services**
7. **Me**

Everything else belongs inside them.

---

## 4. Context System

The OS has three contexts:

* **Academic**
* **Social**
* **Hybrid** (default)

Context changes priority, never architecture.

The navigation remains the same.

---

## 5. Bud Constitution

Bud is the only visible AI.

Bud never exposes Oracle, Spark, Orbit, or internal authorities.

Every interaction flows through Bud.

```
User
 ↓
Bud
 ↓
Oracle
 ↓
Authorities
 ↓
Spark / Orbit
 ↓
Response
```

---

## 6. Orbit Constitution

Orbit is not an assistant.

Orbit discovers verified information.

Responsibilities include:

* Scholarships
* Jobs
* News
* Research
* Sports
* Events
* Movies
* Music
* Public datasets
* University announcements

Orbit never fabricates information.

---

## 7. Spark Constitution

Spark performs work.

Examples:

* OCR
* File processing
* Scheduling
* Automation
* Semantic indexing
* Background jobs
* Caching
* Workflow execution

Spark never owns UI.

---

## 8. Shared Module Rule

Every feature is built once.

Examples:

* Community
* Podcast
* Live
* Story
* Post
* Chat
* Event

Departments, creators, clubs, and societies all reuse the same modules with
different permissions and data.

---

## 9. Zero-Demo Rule

The platform must never display fake content.

Only:

* User-generated content
* Institution-provided data
* Verified external data
* Official integrations

No placeholders, fake statistics, or fabricated feeds.

---

## 10. Navigation Rule

Permanent navigation:

```
Square · Campus · Quad · Connect · Lens · Services · Me
```

Never place:

* Bud
* Orbit
* Spark
* Wallet
* Marketplace

in the permanent navigation.

---

## 11. Hidden Services Rule

Marketplace and Wallet are operating system services.

They appear through:

* Services
* Lens
* Bud
* Context-aware actions
* User workflows

not as primary destinations.

---

## 12. Reusability Rule

A capability can never be implemented twice.

If one workspace needs a feature that already exists elsewhere, it must reuse
the existing module.

---

## 13. AI Governance Rule

Internal authorities are invisible.

They include:

* Oracle
* Architect
* Builder
* Reviewer
* Sentinel
* Scholar
* Integrator
* Monitor
* Scribe
* Banker
* Creator
* Community Builder
* Analyst
* Automator
* Configurator

Users never interact with them directly.

---

## 14. Design Rule

The OS behaves like a premium operating system, not a collection of pages.

Every screen should support:

* Seamless transitions
* Shared layouts
* Adaptive context
* Reusable components
* Consistent motion
* Unified visual language

---

## 15. No Feature Factory Rule

No new feature may be added until it answers four questions:

1. **Which layer owns it?**
2. **Which experience presents it?**
3. **Which shared module implements it?**
4. **Which authority governs it?**

If these cannot be answered, the feature should not be added.
